# Stage 3 — Design

Read:

* `ARCHITECTURE.md`
* `AGENTS.md`

Do not reread `INTENT.md` or `CHALLENGE.md`.

Treat the approved `ARCHITECTURE.md` as the authoritative handoff from Stage 2.

## Goal

Produce a validated, implementation-ready `DESIGN.md`.

## Process

1. Apply the `design-generation` skill to `ARCHITECTURE.md`.
2. Create a draft `DESIGN.md`.
3. Apply the `design-review` skill using:

   * `ARCHITECTURE.md`
   * the draft `DESIGN.md`
4. Fix required issues identified by the review.
5. Surface any issue that would require changing the approved architecture.
6. Produce the final `DESIGN.md`.

## Human Gate

Present the final `DESIGN.md` for human approval.

If design work reveals that the architecture itself must change, stop and return to Stage 2 rather than silently modifying it.

Do not proceed to implementation planning until the user explicitly approves `DESIGN.md`.

## Output

`DESIGN.md`

Stop after Stage 3.
